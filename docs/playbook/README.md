# Web game playbook

How to build the next browser game with an AI orchestrator and AI workers, with less trial and
error. Written from what went right and wrong on Red-Green Open World. It does **not** assume the
next game has the same style, audience, genre or purpose. It does assume the game runs in a browser.

| File | Who reads it | What it is |
|---|---|---|
| [HUMAN_GUIDE.md](HUMAN_GUIDE.md) | The owner (a person) | How to explain a game to the AI: an option sheet for every decision, in plain words, plus the start prompt |
| [GAME_BRIEF.md](GAME_BRIEF.md) | The owner fills it in | The one-page-ish brief the orchestrator builds from |
| [PLAYBOOK.md](PLAYBOOK.md) | The orchestrator | The process: phases, gates, rules, what to show the owner and when |
| [BRIEF_TEMPLATES.md](BRIEF_TEMPLATES.md) | The orchestrator | Copy-and-fill briefs for workers, QA, merges, and parallel sessions |
| [CHECKLISTS.md](CHECKLISTS.md) | Orchestrator, workers, QA, owner | Gates: "done" for a feature, before a push, QA round, owner's ten-minute playtest |

Start a new game: the owner reads HUMAN_GUIDE.md, fills in GAME_BRIEF.md, and pastes the start
prompt from the end of HUMAN_GUIDE.md into a new session.
